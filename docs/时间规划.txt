〇、总体时间轴
  D0（2026-09-15 ~ 17，已完成）：需求分析、ER 评审、数据库 12 表建表灌数据、
      12 实体、12 DAO、连库测试、开发计划制定
  第 1 周：Web 层点火（Servlet+JSP 模式确立，3 组页面）
  第 2 周：剩余基础表页面 + 下拉联动 + 删除保护（9 张基础表全可管理）
  第 3 周：开课管理（多对多写操作第一次实战）
  第 4 周：排课管理 + 冲突检测（MVP 最难一周，允许溢出到第 5 周）
  第 5 周：课表查询三视图 + 全局打磨 → ★ MVP 验收 ★

  反之则拉伸——周数可调，每行"验收"不可调。

────────────────────────────────────────

一、第 1 周：Web 层点火
  任务：
    1. 第一页：DepartmentServlet（@WebServlet("/department/list")）
       + department-list.jsp，cargo:run 跑通，浏览器看到 5 个院系
    2. 确立统一页面风格：导航栏、style.css 表格样式、页头页脚
    3. 学期管理页：列表 / 新增 / 编辑 / 删除
    4. 节次管理页：列表 / 新增 / 编辑 / 删除
  产出：院系、学期、节次 3 组可用页面
  验收：浏览器里完成"新增一个学期 → 列表出现 → 编辑改名称 → 删除"全流程
  学习点：doGet 查询 / doPost 修改的分工；表单中文编码（encodingFilter 已配）；
          编辑保存后用"重定向"回列表（防刷新重复提交）；转发 vs 重定向场景
  检查题：从输入 URL 到看到页面，数据经过哪几站？（口述 MVC 链路）

二、第 2 周：剩余基础表 + 联动 + 删除保护
  任务：
    1. 教室、课程、专业、班级、学生、教师 6 组页面（同第 1 周模板）
    2. 下拉联动：专业页选院系 / 班级页选专业 / 学生页选班级 /
       教师页选院系 / 课程页选开课院系——选项一律从数据库查，禁止硬编码
    3. 删除保护：删除被外键引用的记录时，捕获异常并提示人话
       （如"该院系下还有专业，不能删除"）
    4. 表单非空校验（前端 required + 后端判空双重）
  产出：9 张基础表全部可管理
  验收：9 张表各完整走一遍增删改查；删"有孩子的院系"得到友好提示而非 500 页
  学习点：request.getParameter；下拉联动查询；SQLIntegrityConstraintViolationException 捕获
  检查题：为什么下拉选项要查数据库而不是写死在 JSP 里？

三、第 3 周：开课管理（多对多写操作实战）
  任务：
    1. 开课列表页：按学期筛选（下拉），联表显示课程名/教师名/周学时/班级名单
    2. 新增开课页：学期/课程/教师三个下拉 + 班级多选复选框
       保存 = 先 INSERT offering，再逐条 INSERT offering_class
    3. 编辑开课：中间表"先删该开课全部班级行，再按新勾选重新插入"
    4. 删除开课：确认无 schedule 引用 → 删中间表 → 删开课（孩子先于父母）
  产出：开课模块完整
  验收：新增一条开课挂 3 个班 → 列表显示 3 个班名 → 编辑改成 2 个班 → 删除成功
  学习点：一次表单写两张表；service 层第一次正式登场（多表写逻辑放
          OfferingService，servlet 只调 service，不做业务）
  检查题：保存开课时为什么不能只写一张表？

四、第 4 周：排课管理 + 冲突检测（MVP 最难一周）
  任务：
    1. 排课列表页：按开课分组展示（星期/节次/教室/周次/单双周）
    2. 新增排课页：开课/星期/起始节次/节数/教室/起始周/结束周/单双周
    3. service 冲突检测 checkConflicts(Schedule s) → List<String> 冲突描述：
       教师冲突（经 offering 联查）、教室冲突（直接比对）、
       班级冲突（经 offering_class 联查该开课的全部班级）
       判定 = 星期+节次区间重叠 且 周次区间重叠 且 单双周重叠
       返回非空则拒绝保存并展示冲突详情
    4. 编辑 / 删除排课
  产出：排课模块 + 可复用冲突检测方法（v2 自动排课的裁判）
  验收：故意排同教师同时间 → 被拦截并显示"与 PK00X 冲突（教师 李慧敏）"；
        单双周不同 → 允许保存
  学习点：区间重叠判断 startA<=endB && startB<=endA；多条件联表查询
  难点预警：班级冲突要对排课涉及的所有班级逐一检查；逻辑务必放 service 层

五、第 5 周：课表查询 + 打磨 → ★ MVP 验收 ★
  任务：
    1. 班级课表页：选学期+班级 → 周课表（行=星期 1~7，列=节次 1~10，
       格内显示课程名/教师/教室）
    2. 教师课表页、教室课表页（同一套查询换过滤条件）
    3. 全局打磨：统一导航、空状态提示（"本周暂无课"）、操作结果提示、样式统一
    4. 全链路验收演练
  产出：MVP 完成
  验收标准：浏览器里完成"新建班级 → 开课挂班 → 排课（冲突被拦一次）→
            课表出现"全链路；README 更新；测试数据清理
  学习点：七表 JOIN（此前已预演过 CS2401 课表查询）；星期×节次二维渲染

六、第 6~8 周：阶段二（登录权限 + 个人课表 + 学生选课）
  第 6 周：用户表（账号/密码/角色/关联教师或学生）+ 登录退出 + 权限过滤器
           + 四角色菜单差异（超管兜底页、管理员管理页、教师/学生个人页）
  第 7 周：教师/学生个人课表（按登录人联查，学生=班级必修+个人选修）
           + 学生选课/退课（选修课，选课表挂开课记录）
  第 8 周：权限打磨 + 验收（不同角色登录，看到的菜单和功能不同）

七、第 9~10 周：阶段三（调课审批 + 节假日）
  第 9 周：调课表（含审批状态：待审批/已通过/已驳回）+ 教师发起调课申请
           + 管理员审批/驳回（通过后更新排课）
  第 10 周：节假日停课表 + 课表展示停课标记 + 收尾打磨 + 阶段三验收

八、v2 之后（另行专项规划，不在本表排期）
  方向：JSON API 层（/api/*，复用 service/dao）→ 游戏界面客户端对接
  模拟引擎放 Java 后端：学期推进、培养方案自动开课、自动排课
  （复用 checkConflicts）、学生自动选课、个体行为
  当前已留好的门：专业表、week_type 列、service 层骨架、checkConflicts 接口

九、里程碑与自检规则
  1. 每两周必须有一个肉眼可见的验收点（即上表每行"验收"）
  2. 每周日 15 分钟复盘：本周验收达成了吗？卡点是什么？写三行记录
  3. 连续两周未达验收 → 砍掉本周范围内最不重要的功能，保 MVP 主线
     （没有截止日期的项目，最大的敌人是"永远打地基"）
  4. 任何需求变更：先写决策记录（谁提的、理由、影响），再动代码
